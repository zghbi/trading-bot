# 可核对的规模与设计特点

以下说明当前代码的设计范围。实际运行规模受数据是否就绪、机器资源、策略可用状态和配置约束。

## 周期组合规模

完整周期池有 **14种周期**，一套候选策略从中选择 **3～6个不同的方向周期**。

只计算周期选择，不重复计算排列顺序：

| 一套策略使用的方向周期数 | 周期组合数量 |
| --- | ---: |
| 3个 | 364 |
| 4个 | 1,001 |
| 5个 | 2,002 |
| 6个 | 3,003 |
| **合计** | **6,370** |

计算方式为 `C(14,3) + C(14,4) + C(14,5) + C(14,6)`。前提是完整周期池均有可用数据；实际候选出生时只使用已具备可用数据的周期。

同一周期结构还可以使用不同的方向计算、窗口长度、入场配置与持仓管理配置，形成更大的参数空间。具体选项和范围保留在私有实现中。

**6,370是周期组合的数量，不是当前在跑的数量、已经完成测试的数量或已经合格的数量。配置不同也不保证交易行为不同。**

## 更值得研究的系统特点

| 设计点 | 做法与作用 |
| --- | --- |
| 参数化候选生成 | 从研究范围中生成多种候选，便于分别评估和保留配置 |
| 候选去重 | 使用周期、计算规则及配置形成结构签名，避免仅换名字重复占用研究资源 |
| 模拟后评估晋级 | 候选先积累模拟记录，满足评估要求后进入冠军库；具体标准未公开 |
| 基础策略与冠军并行 | 基础策略独立运行，冠军数量与可用状态满足时，前5套冠军一同参与，最多6套策略竞争开仓机会 |
| 策略状态与账户约束分工 | 各策略分别维护自己的决策和信号；同账户的下单仍受统一持仓约束 |
| 运行规模可调节 | 根据延迟、资源和运行健康状态调整模拟并行规模，不要求穷举全部配置 |
| 过程记录与接续处理 | 对策略身份、处理游标及关键事件进行持久化，支持追踪问题和接续处理 |

“最多6套参与”不等于6套各开一个仓位。大规模配置空间也不能证明盈利能力，需要继续核验实际样本、成本和风险表现。

## 项目介绍简版

> CP210是一个持续开发中的交易研究与执行项目，围绕“周期池—策略生成—并行模拟—合格评估—冠军库—实盘机会竞争”组织研究。完整周期池可形成6,370种方向周期组合，并支持参数化候选、结构去重、独立策略状态与账户统一执行约束。项目目前处在开发验证阶段，希望寻找理解交易、愿意共同研究和核验结果的合伙人。公开仓库展示流程与虚拟示例，生产算法和实际配置保留私有。
